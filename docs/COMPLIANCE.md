# Rules, rights & honesty

How the system follows your rules and the platforms' rules — and which part of
the code enforces each one.

## Copyright

| Element | Source | Why it's safe |
|---|---|---|
| Visuals | Procedural motion graphics drawn by `visuals.py` | Original, generated by code; no game footage, trailers, screenshots, logos or key art |
| B-roll (optional) | Pexels API (`stock.py`) | Pexels licence allows free use and modification; we still credit the videographer; descriptions say it isn't gameplay |
| Music | Synthesised per video by `music.py` | Original; the channel owns it — no Content ID risk |
| Library music (optional) | `assets/music/` | Only used if `assets/music/licenses.yaml` names the licence, source and attribution |
| Sound effects | Generated by `music.py` | Original |
| Fonts | `assets/fonts/` | SIL Open Font Licence / Apache 2.0 (licence files included) |
| Voice | Kokoro‑82M (Apache‑2.0) | Blend of the model's stock voices → an original synthetic voice, not a clone of anyone |

Gameplay you capture yourself could be added later (Rockstar has a policy for
video use of its games), but that would be a deliberate change you make, not
something the pipeline does on its own.

## Trademarks & affiliation

"GTA", "Grand Theft Auto" and "Rockstar Games" are only used to describe what
the videos are about. Every description ends with *"Fan channel — not
affiliated with or endorsed by Rockstar Games or Take-Two Interactive."* Avoid
channel names that look official (e.g. "GTA 6 Official").

## Accuracy (no misleading rumours)

Enforced by `facts.py` + `factcheck.py` on every script, again at QA, and again
right before publishing:

- **Every factual line cites fact ids** from `content/facts.yaml`; each fact
  has sources and a status: `official`, `confirmed`, `reported`, `rumor`.
- **Numbers guard:** every number in a line, title, hook or on-screen card must
  appear in the facts that line cites. Hallucinated numbers are impossible to
  publish.
- **Attribution:** facts marked with `attribution` (e.g. "Rockstar says …") and
  all `reported` facts must be attributed in the spoken line.
- **Rumours are off** (`facts.allow_rumors: false`). If you ever turn them on,
  a rumour line must say it's a rumour, and the word "confirmed" can't be used
  near it.
- **Freshness:** each fact has `recheck_days`. Stale facts block publishing
  until re-verified. Facts with a `verify` block are re-checked automatically
  against their source page every day.
- **Leak/insider language, bait phrases** ("free download", "link in bio",
  giveaways, piracy) and profanity are rejected.
- News headlines are only *leads* (`data/research/`) — never usable as facts.

## AI disclosure

- YouTube uploads set `status.containsSyntheticMedia = true` and the
  description says the narration is AI-generated.
- TikTok posts set `is_aigc = true` (AI-generated content label).
- Descriptions state the visuals are original motion graphics, not gameplay.

## No impersonation

The narrator is an original persona (`channel.persona`). The writer prompt
forbids imitating real streamers or their catchphrases, and the voice is a
blend of synthetic voices — no voice cloning.

## Platform policies

- **YouTube "inauthentic content"** (mass-produced / repetitive videos can't be
  monetised): the originality check rejects scripts too similar to earlier ones,
  each video gets its own theme, background mix, transitions and music, topics
  rotate, and template-written scripts are review-only by default.
- **Spam & misleading metadata:** titles must use only cited numbers; titles and
  hooks are checked like spoken lines.
- **Made for kids:** always `false` (GTA is an adult-rated game).
- **API rules:** we never bypass audits, quotas or account requirements.
  TikTok stays in inbox/private mode until TikTok approves more.
- **Human approval** is required for every upload until you choose Stage 4.

## Data & secrets

- Secrets live only in GitHub Actions secrets; the code never logs them (the
  Gemini key is sent in a header, not the URL).
- The repository is public: code, scripts, statistics and review videos are
  visible. No personal data is stored.
- Review issues can only be approved by the repository owner (the publish
  workflow checks who added the label).
